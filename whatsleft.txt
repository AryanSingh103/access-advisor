AccessAdvisor — What's Left
===========================
Audit date: 2026-07-03
Legend: [BROKEN] doesn't work today · [MISSING] not built yet · [IMPROVE] works but should be better


1. BROKEN / FUNCTIONAL BUGS (fix first)
---------------------------------------

[BROKEN] "Post to GitHub" posts zero comments — the headline feature is dead code.
  backend/routers/github.py:70 — _parse_violations always sets line_number=None,
  and post_comments (github.py:121-122) skips every violation with line_number=None.
  So comments_posted is always 0. Fix: have the LLM prompt return a line number
  (the diff patch includes @@ hunk headers with line info), parse it, and map it
  to the PR diff position. This is the core promise of the app.

[BROKEN] NextAuth GitHub OAuth is configured but never used.
  frontend/src/auth.ts sets up the provider and stores accessToken in the session,
  but no page calls signIn(), useSession(), or auth() — there is no sign-in button
  anywhere. Instead every page makes users paste a raw GitHub PAT into a text field.
  Either wire the OAuth session token into analyzePR/postComments/scanRepo calls
  (the whole point of the OAuth setup), or delete NextAuth entirely.

[BROKEN] Dashboard "Analyze PR" form links to /dashboard/pr/{repo}__{pr} but the
  PR page ignores params entirely (pr/[id]/page.tsx:23 receives params and never
  reads them) — user has to re-type repo, PR number, and token on the next page.
  Parse the id (or use searchParams) and prefill/auto-run.

[BROKEN] Dead "History" link in dashboard sidebar (dashboard/page.tsx:156-161,
  href="#"). Build it or remove it.

[BUG] Relative ChromaDB path: CHROMA_PATH = "./chroma_db" (rag/ingest.py:17)
  depends on the working directory uvicorn is launched from. Start the server from
  repo root and it silently re-ingests into a second, empty DB (paying OpenAI
  embedding costs again). Make it absolute relative to __file__ like DATA_PATH.

[BUG] Dead code: rag/query.py:51-52 computes query_embedding and never uses it
  (the retriever embeds internally). Two embedding API calls per analysis — one
  is wasted money and latency. Delete it.

[BUG] URL scanner sends unbounded HTML to Claude. scanner.py:61 takes the entire
  <body> innerHTML — a large page will blow the context window or cost dollars per
  scan. Truncate/strip (drop <script>/<style>/<svg> contents, cap length) before
  sending.

[BUG] max_tokens=2048 (rag/query.py:74) truncates output on pages/files with many
  violations — the regex parser then silently drops the cut-off violation. Raise it
  and/or detect stream truncation (stop_reason == "max_tokens").


2. SECURITY (must fix before deploying anywhere public)
-------------------------------------------------------

[MISSING] No auth on the backend at all. Every endpoint is open — anyone who can
  reach the API can burn your Anthropic/OpenAI credits. Add at minimum a shared
  API key header checked in a FastAPI dependency, or verify the NextAuth session.

[MISSING] SSRF protection on /api/scan-url. It only checks the scheme, so it will
  happily render http://localhost:8000, http://169.254.169.254 (cloud metadata),
  or internal network hosts. Resolve the hostname and reject private/loopback/
  link-local ranges before launching Playwright.

[IMPROVE] GitHub tokens travel as plaintext JSON body fields through the backend
  and can end up in logs. Once OAuth is wired (see item 1), stop asking users for
  raw PATs entirely.

[MISSING] No rate limiting anywhere. One user can trigger 50 Claude calls per
  repo-scan request. Add slowapi or a simple per-IP limiter.

[MISSING] Streaming UX for the URL scanner. scanner.py buffers the whole Claude

  (e.g. "rendering page", "analyzing", token count) like repo_scan does.

[MISSING] Repo scan silently caps at 50 files (repo_scan.py:16,51) with no
  indication to the user that files were skipped. Emit a "truncated" event and
  show it in the UI.


4. TESTING & CI (currently zero)
--------------------------------

[MISSING] No tests at all — backend or frontend. Highest-value targets:
  - _parse_violations regex parsing (github.py, scanner.py, repo_scan.py) — pure
    functions, easy to unit test, and the whole app depends on them.
  - has_ui_content() filter (rag/query.py).
  - API route tests with FastAPI TestClient + mocked analyze_content.
  Add pytest + a tests/ dir for backend; vitest or jest for frontend lib/api.ts.

[MISSING] No CI. Add a GitHub Actions workflow: backend (ruff + pytest),
  frontend (npm run lint, tsc --noEmit, npm run build). For a portfolio project,
  a green checks badge matters.

[MISSING] No linting/formatting config for Python (ruff/black). Frontend has
  eslint but no CI enforcement.


5. CODE QUALITY / REFACTORS
---------------------------

[IMPROVE] The violation-parsing regex + Fix-extraction logic is copy-pasted three
  times (github.py:45-75, scanner.py:27-48, repo_scan.py:112-134). Extract one
  shared parser module (e.g. backend/rag/parse.py) — three parsers already drifted
  (github's returns Pydantic models, the others dicts with criterion_name).

[IMPROVE] Better than regex: ask Claude for structured output (tool use / JSON
  mode) instead of parsing "[SC x.x.x ...]" prose with regex. Eliminates the whole
  fragile-parsing class of bugs, including the line_number problem in item 1.

[IMPROVE] repo_scan.py has imports and regexes at the bottom of the file
  (repo_scan.py:112-118) below the router. Move to the top.

[IMPROVE] PyGithub is synchronous and is called inside async endpoints
  (github.py, repo_scan.py) — it blocks the event loop during network calls.
  Wrap in asyncio.to_thread() or use httpx directly.

[IMPROVE] sys.path.insert hacks in rag/ingest.py:11 and rag/query.py:10.
  Make backend a proper package (pyproject.toml or run as module) instead.

[IMPROVE] has_ui_content() regex (rag/query.py:16-19) misses semantic HTML:
  <table, <h1-h6, <video, <audio, <iframe, <ul/<ol, <nav, <section, <dialog —
  all of which have WCAG requirements. Files containing only these get skipped.

[IMPROVE] AccessibilityIcon + the header/nav bar is copy-pasted into four pages
  (dashboard, pr/[id], scan/repo, scan). Extract shared <AppHeader>/<Logo>
  components.

[IMPROVE] The AsyncGenerator NDJSON reader loop is duplicated in api.ts
  (scanUrl:89-121 and scanRepo:136-171). Extract a shared ndjsonStream helper.

[IMPROVE] scan_url mislabels its media type: it emits NDJSON but the analyze and
  repo-scan endpoints claim "text/event-stream" while also emitting raw
  tokens/NDJSON (not SSE "data:" frames). Pick one format (NDJSON everywhere)
  and label it application/x-ndjson consistently.

[IMPROVE] CLAUDE.md says "Next.js 14" but package.json has next 16.2.9 and
  React 19 — update the docs (and README if it repeats this).

7. THE APP'S OWN ACCESSIBILITY (it's an a11y tool — it will get judged on this)
-------------------------------------------------------------------------------

[IMPROVE] Form inputs rely on placeholder text only — no <label> or aria-label
  (dashboard, pr/[id], scan/repo pages). Placeholder-as-label is itself a WCAG
  failure (3.3.2).
[IMPROVE] Decorative SVGs lack aria-hidden; icon-only elements lack accessible
  names.
[IMPROVE] Low-contrast text: #52525B on #0F0F12 backgrounds is ~3.5:1 — below
  the 4.5:1 AA requirement for body text (1.4.3).
[IMPROVE] No focus-visible styles beyond border color changes; check keyboard
  navigation through the collapsible file cards.
[IMPROVE] Live scan progress updates aren't announced — add aria-live="polite"
  regions for streaming results.
  → Best move: run AccessAdvisor's own URL scanner on itself and fix what it finds.
    Great README/demo material.
